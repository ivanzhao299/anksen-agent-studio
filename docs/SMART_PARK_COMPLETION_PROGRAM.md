# Smart Park ERP Completion Program

## Goal

全面完善智慧园区 ERP，并以真实代码、真实数据模型、真实 API、真实页面和可重复验证证据作为完成标准。

本计划不把既有文档、菜单、占位页面或 `CONTROLLED_STUB` 的成功结果视为业务模块完成。

## Current evidence baseline

当前仓库已存在资产、招商租赁与财务、租户服务与工单、安全、工程、IoT、能耗、视频、机器人、BIM、AI、驾驶舱和平台治理实现。不同模块成熟度差异显著，且部分二期模块存在“代码可访问、菜单隐藏、独立验收不足”的状态。

战略执行和完整人力资源管理尚未形成对应业务模块。现有组织、用户和角色管理属于平台治理底座，不能替代人力资源系统。

Smart Park 仓库中 `ops/agent-orchestrator` 的运行态队列和事件目录不属于本计划的提交范围。

## Delivery phases

### Phase 0 — Foundation

- 全域能力矩阵：页面、API、实体/表、权限、测试、外部依赖和生产证据。
- 组织、身份、RBAC、数据范围、字段策略、主数据、附件、审计和 SaaS 模块治理收口。
- 统一跨域实体、状态、事件、幂等和审计契约。

### Phase 1 — Core ERP

- 战略执行：战略地图、年度目标、KPI、重点任务、责任分解和复盘。
- 人力资源：组织岗位、员工、招聘、入转调离、绩效、人才盘点与合规。
- 财务管理：预算、应收应付、收款核销、发票、减免退款、能源账单和经营分析。

### Phase 2 — Core park operations

- 资产空间与企业 360。
- 招商 CRM、合同、变更和退租。
- 租户服务、工单、SLA 和流程协同。
- 安全、巡检、隐患、应急和作业许可。
- 工程项目、计划、日报、巡检、整改和验收。

### Phase 3 — Intelligent operations

- IoT 设备、规则和场景联动。
- 能耗监测、分摊、账单与财务衔接。
- 视频安防与事件证据。
- 机器人任务和轨迹运营。
- BIM 数字孪生跨域叠加。
- AI 运营助手的授权查询、分析和受控动作。

### Phase 4 — Management and release

- 董事长与经营驾驶舱。
- 全角色、全权限、全状态机、跨域、移动端和降级回归。
- 迁移、备份恢复、性能、安全、UAT、发布门禁和回滚演练。

## Execution policy

- Program Task 必须由 `smart_park_development` 能力 Worker 领取。
- 实际开发必须使用经过 Activation Gate 授权的 CODEX Runtime。
- `CONTROLLED_STUB` 不得把 Program Task 标记为业务完成。
- 每个 Task 最多一次受控 Attempt；失败后先审计，再决定是否创建新的修复任务。
- 默认禁止 push、merge 和 deploy。发布阶段仍需要明确人工批准。
- 每个业务任务必须独立提交，并在进入下游前完成定向测试和验收证据。

## Definition of done per domain

一个业务域只有同时满足以下条件才能进入 `SUCCEEDED`：

1. 数据模型和迁移可验证。
2. 服务、API 和状态机真实实现。
3. 页面不是占位、兼容跳转或只读演示。
4. 菜单、路由、模块授权、RBAC 和数据范围一致。
5. 高风险写接口具备幂等、审计和冲突保护。
6. 至少一条核心端到端业务链路通过。
7. 单元、集成、构建和领域回归通过。
8. 外部集成具有隔离 Fixture；生产可用性必须另有真实环境证据。
9. 中英文、响应式、空态、错误态和权限态完成产品验收。
10. 形成可重放的验收报告和剩余风险清单。
